# 개념 · 함수 vs 리액트 컴포넌트

> 📂 파일: `index.jsx` — 비교표 + 라이브 데모

리액트 컴포넌트는 **자바스크립트 함수**다. 다만 몇 가지 규칙이 있는 **특별한 함수**다.

## 비교표

| | 일반 함수 | 리액트 컴포넌트 |
|---|---|---|
| 이름 | 소문자 (`add`) | 대문자 (`Hello`) |
| 돌려주는 것 | 아무 값 (숫자·문자 …) | JSX (화면) |
| 부르는 법 | 내가 직접 `add(2, 3)` | `<Hello />` 로 리액트가 부름 |
| 훅(useState 등) | 못 쓴다 | 쓸 수 있다 |
| 다시 실행 | 내가 부를 때만 | 상태 바뀌면 리액트가 다시 부름 (리렌더) |

```jsx
function add(a, b) { return a + b }          // 일반 함수 → 값을 돌려줌
function Hello({ name }) {                    // 컴포넌트 → 화면을 돌려줌
  return <p>안녕하세요, {name}님!</p>
}

add(2, 3)            // 내가 직접 부른다 → 5
<Hello name="김코딩" /> // 리액트가 부른다 → 화면
```

## 🧬 컴포넌트 그 자체 — JSX는 '값'이다

`<Badge />` 같은 JSX는 화면이 아니라 **값(객체)** 이다. 그래서 변수에 담고 return할 수 있다.

```jsx
function Say() {
  const hello = <Badge value="hihi" />  // JSX를 변수에 담고
  return hello                          // 그대로 돌려줘도 된다
}
```

- `<Badge />`는 사실 `React.createElement(Badge, ...)`의 축약 — "무엇을 그릴지 적은 **설명서(객체)**".
- 컴포넌트 = **그 설명서(JSX)를 돌려주는 함수.** 리액트가 설명서를 받아 실제 화면으로 바꾼다.
- (참고: `<Badge>hihi</Badge>`처럼 태그 사이에 넣으면 `children`이 되는데, 우리 `Badge`는 `value`만 그려서 안 보인다 → `value`로 넘긴다.)

## ⚠️ 소문자로 쓰면? — `<say />` vs `<Say />`

리액트는 **소문자 태그를 HTML 태그로** 본다.

| 코드 | 결과 |
|------|------|
| `say()` | ✅ 함수 직접 호출 → 동작 (이름 무관) |
| `<say />` | ❌ 소문자 = HTML 태그로 인식 → 빈 `<say>` 요소, 함수 무시 |
| `<Say />` | ✅ 대문자 = 컴포넌트로 인식 |

`<say />`는 에러도 없이 **조용히 안 나온다** — 그래서 더 헷갈린다.

### 내 컴포넌트를 소문자로 만들면? (예: `div`)

정의를 소문자로 해도 소용없다. 리액트는 **이름의 첫 글자**만 보고 판단한다.

```jsx
function say() { return <Badge value="3" /> }   // 소문자로 정의해도
<say />   // → 함수 무시, 빈 <say> 요소만 생김

function div() { return <Badge value="3" /> }   // HTML 태그와 이름이 겹치면
<div />   // → 진짜 HTML <div>가 그려진다. 내 함수는 완전히 무시됨
```

- 소문자 태그 = **HTML 태그로 취급** → 내가 만든 함수는 호출되지 않는다.
- 그래서 컴포넌트는 **반드시 대문자**로 시작한다.

## ⚠️ 또 하나

- 컴포넌트를 `Hello()`처럼 **직접 부르지 말고** `<Hello />`로 쓴다.
- 그래야 리액트가 **컴포넌트로 인식**해 상태·리렌더·key를 관리한다.

## 한 줄 정리

> **컴포넌트 = 화면(JSX)을 돌려주는, 리액트가 `<이름 />`으로 부르는 함수.**
