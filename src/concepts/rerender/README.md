# 개념 · 리렌더링 조건 (언제 다시 그려지나)

> 📂 파일: `index.jsx` — 리렌더 조건 정리 + 라이브 데모

**리렌더(re-render)** = 컴포넌트 함수를 **다시 실행**해 새 화면을 계산하는 것.
`UI = f(props, state)` 이니, 입력이 바뀌면 f를 다시 돌린다.

## 다시 그려지는 3가지 조건

1. **자기 state가 바뀔 때** — `setState`(예: `setCount`)
2. **받은 props가 바뀔 때** — 부모가 새 값을 넘김
3. **부모가 리렌더되면 자식도** — 기본 동작 (자식 props가 그대로여도)

> ＋ 구독한 **Context** 값이 바뀔 때도 리렌더된다. (8단계)

## 데모로 확인

- **부모 state 버튼**: 자식에게 아무것도 안 넘겼는데도, 부모가 다시 그려지니 자식도 다시 그려진다(③).
- **자식 state 버튼**: 자식만의 state라 자식만 다시 그려진다(①).
- (자식의 "마지막으로 그려진 시각"이 바뀌면 = 다시 그려졌다는 증거)

## 알아두기

- 리렌더가 잦아도 리액트는 **가상 DOM**으로 실제 바뀐 부분만 DOM에 반영한다 → 대개 걱정 불필요.
- 정말 느릴 때만 `memo` 등 최적화를 **나중에**. (조기 최적화 금물)

## ❌ 오해

- 일반 변수(`let x = ...`)를 바꿔도 리렌더되지 않는다. 화면과 연결된 **state/props**여야 한다.
